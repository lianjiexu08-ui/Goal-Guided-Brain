# GGB 手机端交互规范

本文定义 Goal-Guided Brain 在手机端的交互边界。手机端不是桌面侧栏的缩小版，而是围绕“当前工作”和“下一步动作”组织的单列工作流：用户随时可以继续招募、切换团队、查看待处理任务，输入内容和附件不能因为导航变化而丢失。

## 1. 信息架构

手机端只保留四个高频入口，固定在底部安全区上方：

| 入口 | 作用                                       | 进入后的默认状态                                     |
| ---- | ------------------------------------------ | ---------------------------------------------------- |
| 招募 | 发布新的需求，与项目经理多轮澄清           | 当前未确认的招募草稿；没有草稿时创建一份新的招募草稿 |
| 团队 | 查看已确认团队的目标、成员、风险和最近动态 | 当前选中的已确认团队；没有已确认团队时回到招募       |
| 任务 | 查看所有团队的执行状态、风险和待复核交付   | 任务中心，保留上一次筛选条件                         |
| 更多 | 打开完整导航抽屉                           | 助手、能力、知识库、模型、节点和设置                 |

顶部的“当前工作”栏始终显示当前上下文。它包含工作名称、团队目标或招募阶段，以及“切换”按钮。切换按钮打开底部面板，面板按“需求发布 / 我的团队”分组；已确认团队支持按名称和职责搜索。完整导航抽屉用于低频管理，不承担团队快速切换的主要路径。

## 2. 状态切换规则

手机端切换的是工作上下文，不是新建一次对话：

1. 点击“团队”时，进入当前已确认团队；如果没有已确认团队，进入团队招募并保留招募草稿。
2. 点击“招募”时，回到当前未确认的招募草稿；点击“另起一个需求”才创建新的独立草稿。
3. 从当前工作栏切换团队后，关闭切换面板，打开目标团队的项目经理对话，恢复该团队和角色对应的草稿、附件和会话。
4. 切换团队会关闭任务详情、重置团队动态筛选，并且不能把上一个团队的输入、附件、任务或消息渲染到当前团队。
5. 从完整导航选择一个页面后，导航抽屉自动关闭；底部导航仍然反映当前页面。打开设置、知识编辑、任务详情等面板时，底部主导航暂时隐藏。

页面刷新后恢复最后一次有效的团队、角色和视图。服务端轮询或实时事件刷新只能更新数据，不能把用户带回默认页面，也不能清空输入框。

## 3. 输入、键盘和附件

- 输入框使用至少 16px 字号，避免 iOS 自动放大；发送按钮和附件入口至少 44px 触控尺寸。
- 输入框获得焦点后，底部主导航隐藏；编辑区贴着 Visual Viewport 的可见底部，并保留安全区内边距，键盘收起后导航恢复。
- 发送按钮固定在输入区内部，输入区不能被底部导航或系统键盘遮挡；用户可以在单列页面中滚动查看历史消息。
- “添加文件”、拖入和粘贴都传输文件本身。界面展示文件名只是预览，发送请求引用附件 ID；切换团队不会复用另一个团队的附件。
- 切换页面、打开切换面板或刷新时，对话草稿按“团队 + 角色”保存到服务端，本地缓存用于短暂离线；冲突时显示本机和远端版本，不能静默覆盖。
- 协作表单按来源团队、处理说明按原协作独立同步。冲突版本在手机上单列展示，完整文本可选择复制；先核对版本再提交。另一设备可继续确认待发送请求，原设备仍可重试同一 ID，不能重复派发或清掉后续新草稿。

## 4. 面板和返回行为

手机端的设置、团队设置、模板、知识和切换团队都使用底部面板：面板最高不超过可见视口的 92%，标题固定可见，长表单在面板内部滚动，主提交按钮保持可触达。遮罩点击和显式关闭按钮都应关闭面板，不应改变当前团队或草稿。

系统返回键和边缘返回手势遵循同一层级：优先关闭最上层面板，其次关闭完整导航抽屉；关闭后仍停留在当前工作台，只有没有应用层状态可关闭时才允许浏览器返回离开工作台。面板关闭会清理对应的编辑状态，不会清空草稿或改变团队上下文。

## 5. 风险、通知和离线

- 团队风险和待处理事项在团队列表、底部“任务”入口和切换面板中显示数量；数量只代表需要用户介入的事项，不代表普通消息数。
- 连接中断时保留当前页面和草稿，显示服务未连接状态；恢复连接后先回放服务端游标，再刷新当前团队，不能重复发送消息。
- 团队暂停、预算耗尽、任务失败和交付被拒绝都必须能从手机端风险入口打开对应团队或任务，并提供恢复、重试或确认动作。

## 6. 手机端验收清单

每次涉及导航、输入、团队或任务的改动，都至少在 390px 宽度下验证：

- 招募、团队、任务、更多四个入口可互相切换，激活态和系统返回位置正确；
- 当前工作栏能搜索并切换多个团队，草稿和附件按团队隔离；
- 模型启动检查在 320px 窄屏下保持可读，配置入口至少 44px 高且完整可达；跳转模型管理或解锁凭据后返回招募页，保留需求草稿，状态随配置变化更新；
- 键盘打开时输入区、发送按钮和附件入口可见，底部导航不会遮挡内容；
- 任务详情、设置和团队设置面板在安全区内可滚动，提交按钮可见且可点；
- 风险数量、实时团队动态、断线回放和恢复动作仍然可用；
- 页面根节点和内部可滚动容器（如团队动态页）的 `scrollWidth` 都不超过各自可见宽度；长团队名称和职责不得撑开列表。打开、定位或关闭协作链路后，页面横向滚动位置仍为 0，面板左右边界位于视口内；
- 多团队协作链路显示每次请求的来源和目标、追问与转派关系；执行任务和发起任务入口均可触达，切入任务后恢复所属团队的对话；
- 整条协作链路收尾使用内联预览，全部范围可独立滚动，长团队名称换行；说明输入至少 16px，按钮至少 44px，勾选与确认必须可触达。说明跨刷新恢复，其他设备修改说明后取消旧确认；明确拒绝保留输入，未知结果可用同一请求重试；
- 系统返回键或边缘返回手势先关闭面板/导航抽屉；桌面宽度下不显示手机底部导航和手机切换面板，原有侧栏行为不回归。

当前代码已经覆盖导航、团队搜索、草稿/附件隔离、底部面板、键盘态布局、系统返回和横向溢出回归；真正的 iOS/Android 真机和离线网络切换仍需单独验收。
