# 个人智能体产品方向

这个项目的目标是一个只服务于自己的智能体，而不是把几个模型的聊天接口并排放在一起。模型是可替换的执行引擎；真正稳定的是你的工作习惯、记忆边界、权限规则、任务流程和结果格式。

## 默认行为

智能体收到任务后遵循以下顺序：

1. 读取个人偏好、当前项目规则和相关知识。
2. 判断任务属于咨询、资料整理、规划、编码、审查或外部操作。
3. 选择合适模型和工具；模型失败时按候选顺序切换，但不重复已经产生副作用的工具调用。
4. 高风险操作先说明影响并请求确认；低风险的读取、分析和验证可以连续完成。
5. 给出结果、证据、未完成事项和下一步；没有实际发生的操作不得声称完成。
6. 把明确的长期偏好保存为个人规则，把一次性要求留在当前会话。

## 个人偏好

网页的“工作空间设置”现在可以保存称呼、时区、语言、语气、详细程度、工作习惯、长期规则和补充说明。它们会进入新任务上下文，当前任务要求和助手权限优先于个人偏好。

偏好分三类：

- 表达偏好：语言、语气、详细程度和输出格式。
- 工作习惯：例如“先给结论，再给证据”“修改后必须运行测试”。
- 长期规则：例如“不主动推送或部署”“没有证据不标记完成”。

以后会增加按项目覆盖的偏好，但不会把项目规则混进全局个人记忆。

## 四种工作模式

这是产品行为层，而不是四个固定机器人：

- **咨询**：只分析和回答，不修改文件。
- **计划**：先拆目标、约束、步骤和验收标准，等待执行或继续指令。
- **执行**：可以读写文件、运行验证和调用已授权工具。
- **复核**：只检查成果、差异、测试和证据，默认不再扩大修改范围。

同一个会话可以从计划切到执行，再切到复核；模型可以中途更换，个人偏好和会话上下文保持不变。

## 模型分工

不把模型绑定到人格。路由器按任务特征选择模型：

- 低延迟问答和整理：便宜、响应快的模型。
- 复杂规划、架构和长上下文：长上下文模型。
- 代码修改和工具调用：工具能力稳定、输出结构可靠的模型。
- 复核和高风险操作：独立模型或不同供应商交叉检查。

用户可以指定模型；未指定时由路由器选择。模型切换记录在会话事件中，失败切换不会丢失原始请求、工具结果或预算统计。

## 记忆边界

- 全局个人偏好：只保存明确的长期工作方式。
- 项目知识：只对对应工作目录生效。
- 会话历史：保存任务上下文、模型切换、工具调用、结果和检查点。
- 临时上下文：只在本轮有效，压缩时可以丢弃。

任何来自模型、网页内容、Skill 或 MCP 的文本都不能自行修改个人偏好或扩大权限；需要用户确认或明确的保存动作。

## 当前已交付

- 统一 `dsh` CLI，支持 Gemini、Claude、Codex/OpenAI、Kimi、DeepSeek。
- JSONL 会话、`--continue`、`--session` 和稳定 `--json` 事件。
- 个人 Profile 持久化、API 和网页设置面板。
- 个人偏好自动注入任务上下文。
- 多供应商路由、凭据隔离、MCP 工具网关、任务组、检查点和隔离执行目录。

## 下一步

优先实现统一 Agent Core，使 CLI、网页和后台任务共用同一事件流，然后加入 `dsh --mode rpc`、分支会话、自动上下文压缩、项目级设置和可拦截的工具 Hook。这样“服务个人习惯”会成为系统内核，而不是某个页面上的提示词。
