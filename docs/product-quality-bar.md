# GGB 产品质量标准

本文是 Goal-Guided Brain 的本地开发和发布门槛。它把“高专业度、高审美、交互完整、代码可维护”变成可以检查的规则；视觉稿、实现和测试必须以同一套规则为准。

## 1. 产品体验标准

GGB 面向一个人管理多个长期运行的智能体团队。界面首先要让用户知道“我现在在哪个团队、谁在工作、做到哪一步、下一步要我决定什么”，再展示模型和工具细节。

- **上下文明确**：当前团队、项目经理、任务状态和工作目录在页面标题或上下文栏中可见。切换团队、刷新、实时更新和断线重连不得改变上下文或清空草稿。
- **状态可解释**：加载、同步中、已保存、离线、冲突、阻塞、待验收和已交付使用不同文案和视觉层级；每个不可执行状态都提供下一步动作。
- **证据优先**：模型回复不能单独表示交付完成。任务必须分别显示执行状态、验证证据、所有者决定和交付状态。
- **风险可恢复**：失败、预算耗尽、权限不足、模型不可用、能力缺失和网络中断都要说明原因、影响范围和恢复入口。
- **渐进披露**：普通用户从团队招募开始；模型、Skill、MCP、Plugin、节点和凭据属于配置面，不阻塞一次正常需求的完成。

## 2. 视觉和交互标准

视觉方向是“安静、清晰、可信的工作台”，不是营销落地页，也不是把所有信息堆成监控面板。

- 颜色只表达语义：绿色代表可继续或已验证，琥珀色代表需要关注，红色代表阻塞或失败；普通装饰不能使用风险色。
- 页面使用一个主要行动和最多两个次要行动；破坏性动作、发布、外部写操作和交付确认必须明确标注影响。
- 字体层级、间距、边框和圆角来自统一设计令牌；组件不能在页面中临时创造相近但不一致的值。
- 所有可操作控件在触屏下至少 44×44px；输入框默认 16px，避免移动 Safari 自动放大；焦点、悬停、按下、禁用和错误状态必须可见。
- 手机端采用“招募、团队、任务、更多”四个高频入口；底部导航不遮挡输入区、键盘或安全区。桌面侧栏和移动切换面板不能同时出现。
- 弹层必须能用遮罩、关闭按钮和系统返回关闭；长表单在弹层内部滚动，提交动作始终可达。
- 空状态要说明为什么为空以及下一步做什么；加载状态不能用空白区域冒充完成。
- 对话搜索必须包含尚未展开的历史，提供匹配片段、空结果提示、清空和完整结果访问；选择结果后定位原文并保留草稿，关闭后正确恢复焦点。搜索范围随团队和成员会话切换，不能混入其他上下文；手机端面板与关闭按钮必须完整位于可视区内，系统返回须先关闭搜索而不离开工作台。
- 长对话首屏限制同时渲染的轮数，但必须能完整展开历史；补载、上方内容增高及实时更新不能挤掉正在阅读的内容。团队和成员会话切换须隔离阅读窗口，回到最新能恢复跟随；手机窄屏下标题、历史入口和输入区不得挤占全部正文空间。
- 输入区必须在 320px、390px、1024px、1280px、1440px 下容纳长模型名称、长工作目录和错误提示；发送及模型切换控件完整可见、实际可点击，详情展开不遮挡控件。页面没有横向滚动不能替代按钮可达性检查。
- 筛选切换后立即隔离旧列表、统计和游标；迟到的成功或失败响应均不得覆盖当前筛选。初次读取失败不得显示“没有风险”或零计数；同一筛选刷新失败要保留上次结果并说明时效；分页失败须保留已加载内容并重试原游标。

## 3. 代码和工程标准

- TypeScript/React 遵循项目的 `oxlint`、TypeScript 严格模式和 `oxfmt`；Node.js 使用 ESM、明确的输入校验和错误边界。
- Python（如未来加入脚本或工具）遵循 PEP 8、类型标注和格式化检查；不得用 PEP 8 约束 JavaScript/TypeScript 文件。
- 手写源文件不超过 1000 行，单个 React 组件和单个服务模块也应按职责拆分。行数门禁会扫描当前实现和未跟踪的新文件；超过限制的文件必须在提交前拆分，不能把超长文件带入主分支。
- UI、领域状态、API 客户端和纯函数分离；网络请求不能散落在展示组件中，跨页面复用的状态机必须有独立模块和测试。
- 业务状态转换必须可通过确定性测试复现；时间、随机数、供应商请求和文件系统都要提供测试替身。
- 执行详情须区分实时更新、重连、定时更新、离线和读取失败，并提供最近成功读取时间与重试入口。首次失败、超时或损坏响应不得伪装为空结果；刷新失败保留证据和未提交验收备注。断线恢复与任务切换隔离迟到响应，读取期间收到的新事件不得被旧快照覆盖；事件游标在不足一页时仍推进，空页保留原游标。
- 页面关闭或切换后，未完成的前台请求和事件流须释放上游连接；晚到响应不得向关闭的连接写入。正常断开不能伪装成服务故障，真实异常不能被取消逻辑吞掉。使用真实生产适配器和 HTTP 连接验证，不能只模拟浏览器的 AbortController；任务的持续执行与前台连接生命周期分离。
- 不以压缩代码、关闭 lint、增加 `any`、跳过类型检查或把测试改成快照来绕过质量门槛。
- 状态读取性能必须用可复现的数据规模测量；共享集合不得随任务数逐个重复读取。请求内索引不能跨请求保留，必须覆盖其他数据库连接写入、删除、需求版本变更后的新鲜度，不能通过隐藏历史或延长测试时限冒充优化。
- 首屏不得预载未打开团队的活动正文；延后字段须显式标记，默认 API 协议保持兼容。团队动态按当前团队/筛选读取，先筛选再分页，不能漏掉较旧的匹配证据。首次失败不能显示为空列表，分页失败保留内容和游标，切换上下文隔离迟到响应；刷新已展开窗口须同步旧记录修改和删除。手机筛选和刷新按钮的触控高度至少 44px。
- 条件刷新必须在登录验证后处理，保留错误恢复和主动完整刷新；304 必须匹配本地版本，迟到响应不能更换当前校验标记，增量更新也必须与已确认的完整状态收敛。正文省流量指标不得包含响应头，也不得据此宣称服务端计算被省略。状态差异须覆盖新增、修改、删除与顺序，合并不能修改已接受的基线；缓存必须按工作台隔离并限制容量和期限，基线不可用时返回完整状态。损坏或过期差异须保留当前内容与草稿，并可通过完整读取恢复。
- 跨团队派发必须显式选择目标，修改目标或输入后重新审阅。未确认回执的请求保留原内容和幂等 ID，刷新后可继续确认；成功回执缺少任务 ID 不能清空输入。任务、逻辑任务和双方消息应一起提交，失败不得留下成功记录或发布成功事件。已完成任务不占用活跃任务限额。
- 协作链路必须校验双方消息、任务关联和结构化来源，仅沿有效追问或转派关系读取共享记录。完整关联视图仅供所有者查看，智能体的读取权限不得扩大。转派来源必须取自执行租约，并与任务及双方消息原子保存；成员子任务与重试需验证逻辑作业归属，不得依赖自由文本或客户端自报来源。追问和当前发起任务的关系应同时保留，共享后续只计一次；历史缺失来源不得猜测补齐。分页绑定团队、根请求和链路结构版本；结构变化拒绝旧游标，刷新重读已展开历史。缺失引用显式提示，执行、验收和收尾分别计数；失败保留原内容并提供重试，关闭后恢复入口焦点。
- 整条链路收尾必须预览全部关联请求，包含未展开的历史及多个起始请求。来源不完整、执行未结束或验收条件不满足时逐项解释阻塞；预览后范围、正文、回传、结果、验收或收尾变化须拒绝整批提交。全部决定、审计、回执和草稿清理原子提交；重复请求只确认原回执，不影响新增分支或后续决定。另一设备改变说明后原勾选失效，收尾和重新打开均不启动或停止任务。
- 协作表单和处理说明必须按来源团队/请求同步，冲突展示完整双版本，不能自动拼接目标与正文；服务端待确认请求不得被未审阅的本机版本覆盖。确认请求先持久化固定身份，再提交业务；业务与草稿清空原子完成并保留清空版本。业务回执丢失仍可刷新重试同一请求，迟到回执不清除新草稿。处理中的状态须持续到业务回执和草稿同步均完成，不能提前启用入口，让新打开的面板被旧提交关闭。不同设备和同浏览器标签页均须覆盖离线恢复与并发确认。
- 模型启动状态必须依据聊天协议、启用状态、模型列表和凭据元信息；当前选择的凭据问题不能被其他供应商掩盖。配置检查不得自动发起付费探测，不得将配置完整当作网络已连通，也不得要求安装可选决策后端或能力扩展。去配置或解锁后返回原会话须保留草稿。
- 执行环境检查须区分目录存在、读取/进入权限、写入权限及引擎文件发现，不把找到文件当作运行成功。检查仅读取本机信息，不修改目录/配置或发起任务；输入变化隔离迟到响应，错误和超时提供重试，旧结果明确标明时效。
- 每个用户可见功能至少有一个真实浏览器场景；涉及团队隔离、权限、重试、网络中断或文件内容的行为必须有后端/HTTP 测试。

## 4. 本地验证门槛

在本地提交前按顺序执行：

```bash
npm run quality:lines
npm run format -- --check
npm run lint
npm run typecheck
npm test
npm run test:e2e
npm run build
npm run test:e2e:production
```

`npm run quality:lines` 会递归检查 `app/`、`components/`、`hooks/`、`server/`、
`lib/`、`scripts/` 和 `tests/` 中的手写 TypeScript、JavaScript、Python 与 CSS
文件。它默认列出
所有超过 1000 行的文件并以失败退出；只检查当前改动时使用
`npm run quality:lines -- --changed HEAD`，需要机器可读结果时追加 `--json`。
增量模式同时包含未跟踪的新源文件，避免新文件绕过门禁。检查集合排除构建产物、
依赖目录和测试 fixture。当前全量扫描没有超限文件；如果后续出现超限，必须先拆分
并通过门禁，不能用白名单永久豁免。

`npm run test:e2e:production` 使用最近一次生产构建启动隔离的 API/UI 服务，沿用相同测试与临时数据，不连接日常工作台。必须先运行 `npm run build`；可在命令后追加测试文件。手机弹层和关键表单需要同时在开发模式与生产构建验证，避免 CSS 压缩引入的布局差异。

浏览器回归至少包含桌面 Chromium 和 390px 移动 Chromium。每个改动都要检查 `git diff --check`、真实 API/UI 健康请求和关键流程截图或可复现的 Playwright 断言。

当前已覆盖招募、团队隔离、模型切换、附件二进制、任务交付、实时事件、离线草稿恢复、系统返回键和移动导航的 Chromium 回归；真正的 iOS/Android 真机仍需单独验收。浏览器自动化和代码行数门禁通过不等于真实设备或生产环境验收完成。

## 5. 交付纪律

本地开发优先。未通过上述门槛前不推送、不部署、不声称完成。每个提交只解决一个可以说明和验证的产品问题，提交说明包含行为变化、验证命令和已知边界。线上发布必须另有明确授权，并附带构建产物、测试结果、回滚方式和环境证据。
