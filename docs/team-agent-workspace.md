# Goal-Guided Brain 团队智能体空间

Goal-Guided Brain 把“助手”分成两层：

- **角色智能体**：产品助手、开发助手、智能助手和项目经理各自拥有职责、工具、Skill、模型和候选供应商。单独进入角色页面时，它们就是独立会话。
- **团队空间**：用户只需要和项目经理沟通。项目经理读取需求和团队上下文，按职责调用其他智能体，等待结果后汇总回复。

## 一条需求如何流转

```text
用户消息
  → 团队空间保存 request
  → 项目经理任务（独立 PM 会话）
  → delegate_task 创建产品/开发/资料子任务
  → 子任务通过现有 MCP 协作、任务板、检查点和产物汇报
  → 任务组等待所有子任务完成
  → 项目经理汇总任务
  → 团队空间保存 reply
```

## 入口设计

工作台的主入口是团队招募。用户不需要先判断这件事该交给产品、开发还是资料助手；项目经理先通过多轮对话理解目标、交付物和约束，再生成 Team Charter。方案展示建议人数、每个成员的职责与交付物，用户点击确认创建后才配置成员并开始分派工作。角色列表保留在“助手与模型”管理页和团队成员面板中，用于配置与查看执行状态。团队空间页作为进展检查和成员详情页，与团队招募共享同一条团队消息和任务记录。

每个团队招募空间都可以沉淀成一个独立团队。团队空间本身是一个外层容器，不强行把多个角色塞进同一 session；每个智能体仍保留自己的上下文和模型路由，`spaceId`/`teamId` 负责把项目经理、子任务和用户可见的团队消息关联起来。团队可以配置 `teamType`（开发、运维、产品等）、`purpose`、成员职责、项目经理、工作目录和自治预算。招募状态保存在 `recruitment` 中，经历 `discovery`、`proposed`、`confirmed` 阶段；用户确认后，团队内部仍可按各自的 `autonomy` 自驱执行，团队之间通过受控协作请求交接工作。

团队招募输入框旁提供模型选择器，选项以“供应商 · 模型”显示。选择会保存到当前团队；下一轮招募消息会把精确的 `providerId` 和 `model` 传给项目经理任务，并在执行快照中记录实际路由。没有工具调用能力的模型会进入纯文本模式，避免把文本模型误当成开发工具模型。

后端同时提供 `/api/teams`（兼容 `/api/spaces`）接口：`POST /api/teams` 创建团队，`PUT /api/teams/:id` 更新配置，`GET /api/teams/:id/collaborators` 查看允许协作的团队，`POST /api/teams/:id/collaborate` 将请求投递给目标团队项目经理。跨团队请求受源团队 `collaboration.enabled` 和 `allowedTeamIds` 限制；开启协作且白名单为空时会包含之后新建的活动团队，并在目标团队生成独立任务组。委派消息会在源团队和目标团队各保留一条关联记录，双方可以通过同一个 `taskId` 查看进度。

运行中的智能体还可以通过编排 MCP 的 `list_teams`、`delegate_to_team` 和 `read_team_task` 发现、委派和读取获准的团队任务。委派任务使用目标团队自己的项目经理、模型、能力、预算和工作目录；来源团队不能直接读取目标团队的私有消息。

## 模型选择

每个角色继续使用自己的 `model` 和 `providerIds`。因此可以把项目经理配置成擅长规划和长上下文的模型，把开发助手配置成擅长代码和工具调用的模型，再给产品助手配置检索或写作更合适的模型。没有指定角色模型时，才跟随工作台默认模型。

## 能力绑定

Skill、MCP 和 Plugin 在能力中心安装、启用和固定版本，再绑定到具体助手。任务启动时，运行时只注入该助手已绑定且启用的能力：Skill 以 Skill 文件提供，MCP 以受控工具连接提供，写操作仍按工具授权策略处理。智能体可以调用只读的 `list_capabilities` 查看本次执行的能力目录；对于已绑定且允许调用的 Plugin 命令，可以使用 `run_capability_command` 排队创建受控子任务。它不能从任务中自行启用未绑定的能力，也不能通过命令扩大父任务授权。

## 当前约束

- 团队空间默认使用项目经理角色，最多 4 层子任务、32 个任务，并沿用任务组 Token 预算。
- 项目经理仍必须通过现有编排工具分派任务；前端不会伪造成员完成状态。
- 需要用户批准的外部写入、发布和部署动作不会因为进入团队空间而自动获得批准。
- 团队空间消息和任务组事实分别存储：用户↔项目经理使用 `space-messages`，智能体之间继续使用现有 `messages` MCP。
